# 跨模型退化循环参数观察记录

> 这里记录历史案例中的参数观察，不是通用修复方案，也不保证适用于
> MiMo、GLM 或其他模型。没有重复实验时，不把相关性写成因果关系。

## 核心参数

### maxTokens: 8000（历史案例值）

当时认为 8000 足以覆盖该类单轮工具调用和总结回复；这不能证明 8000 会阻止循环，
也不能推出 12000 或 4000 的通用结论。实际上限应根据任务长度、服务商限制和成本
单独评估。

### timeoutSeconds: 180（历史止损值）

180 秒曾被用作“允许正常任务完成、限制异常资源占用”的折中值。不能据此断言某个
模型在 60—120 秒内必然形成循环；生产值必须根据任务 SLA 和超时记录校准。

### reasoning 参数

某些历史案例中，`reasoning=True` 与重复输出同时出现。这只是相关观察，不能证明
reasoning 是根因；`reasoning=False` 也不能保证不会循环。是否启用 reasoning 应按
模型官方能力、任务需求和实际观测决定。

## 不应直接外推的参数结论

| 参数 | 历史观察 | 当前边界 |
|---|---|---|
| `temperature` | 单次调高未打断已形成的循环 | 不足以证明对其他模型无效 |
| `frequency_penalty` | 单次调整未打断已形成的循环 | 不足以证明通用无效 |
| `presence_penalty` | 没有充分对照实验 | 不作结论 |
| `contextWindow` | 个别压缩尝试未改变现象 | 不能外推到其他上下文实现 |

## 如何做可分享的参数复盘

每个案例至少保留：模型精确版本、供应商/端点、任务集、样本数、完整参数摘要、
上下文规模、是否使用工具、循环判定标准、检测延迟和结果。公开前删除 API Key、
用户内容、隐私字段和完整敏感工具参数。

参数调整只能作为待验证实验变量，不应写成“修复前/修复后”的通用保证。没有足够
样本时，使用“观察到”“可能相关”“尚未复现”。

## 跨框架说明

如果在 vLLM、SGLang 或直接 API 调用中观察到类似现象，可以复用本项目的记录字段
和检测思路；具体参数名、默认值和超时行为必须以对应框架及供应商官方文档为准。
